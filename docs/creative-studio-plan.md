# Креативна студія: агенти для креативів і текстів (план)

Задача (2026-10-22): клієнт дає вимоги, ланцюжок агентів аналізує його, конкурентів і поточні креативи, збирає ТЗ, пише тексти й через Higgsfield робить креативи, які йдуть на затвердження людині.

## Рішення (узгоджено з користувачем)
- Живе в «AI Agents → Кампанії» (розширюємо команду кампанії, не новий розділ).
- Перші креативи: статичні картинки (відео потім).
- Матеріали клієнта (логотип, фото продукту, приклади стилю) менеджер завантажує у форму запиту, вони йдуть у Higgsfield як референси.
- Нічого не публікується і не вантажиться в рекламні кабінети: результат лише на затвердження.
- Будуємо локально, на прод тільки за словом користувача.

## Схема ланцюжка (один запит = один проход)
```
Запит (форма: вимоги, формати, матеріали)
   ├─ Аналітик клієнта   (вимоги + сайт + поточні креативи)  ┐
   └─ Аналітик конкурентів (сайти конкурентів, приклади)      ┴─> Автор ТЗ ─┬─> Копірайтер креативів (якщо треба текст)
                                                                              └─> Виробник креативів ─> Higgsfield ─> перевірка ─> затвердження
```
Запити живуть окремо від тижневої роботи кампанії: власний запис `ag_creative_requests`, завдання агентів несуть `request_id`.

## Етапи
1. **Етап 1 (без Higgsfield):** форма запиту, 5 ролей (аналітик клієнта, аналітик конкурентів, автор ТЗ, копірайтер, виробник у режимі «готує промти»), ланцюжок за запитом, результати на сторінці запиту, ТЗ у вигляді JSON-концепцій, промти для Higgsfield.
2. **Етап 2:** коротка перевірка Higgsfield API (референси, формати, кирилиця на картинці), виробник картинок, перевірка результату (vision), галерея затвердження («прийняти», «переробити з коментарем»), ліміт витрат.
3. **Етап 3:** відео, варіанти, зворотний зв'язок з результатів реклами.

## Ризики
- Фідельність продукту й логотипу: текст у картинку не довіряємо (кирилиця), продукт тільки з референсів.
- Креативи конкурентів: Meta Ad Library автоматично не вивантажується, аналіз за сайтами й ручними прикладами.
- Для нового клієнта немає даних кабінету: аналітик клієнта працює з сайтом і матеріалами.
- Витрати Higgsfield: ліміт на запит і кількість варіантів.

## Відділ креативів: склад і назви (2026-10-23, узгоджено з користувачем)
Відділ на карті агентів («Performance-креативи» перейменовано на «Відділ креативів», розташований поруч зі «Стратегія та дослідження»), 6 агентів:
1. Агент креативний стратег (був «Креативний стратег»): керівник відділу, з запиту менеджера й даних складає план по клієнту й ставить задачі Агенту по ТЗ.
2. Агент аналітик креативів (був «Аналітик ефективності креативів»): раз на тиждень аналізує креативи Meta, віддає висновки стратегу, потім вимірює результат наших креативів.
3. Агент по ТЗ (був «Автор ТЗ»): з плану стратега складає ТЗ для Агента креативщик і для Агента копірайтер.
4. Агент копірайтер (було два: «Копірайтер для performance-реклами» і «Копірайтер креативів»): один агент, два режими (вручну й за ТЗ); злиття в коді ще попереду.
5. Агент креативщик (був «Виробник креативів»): запит у Higgsfield і готові картинки.
6. Агент перевірки якості (був «Контролер якості AI», перенесено з відділу «Контроль якості AI», який зник з карти): перевіряє роботу копірайтера й креативщика, повертає на переробку (до 2 кіл), готове віддає менеджеру.
Дослідження бізнесу й конкурентів лишаються у відділі «Стратегія та дослідження» і постачають стратега.
Цепочка: менеджер -> Агент креативний стратег (<- Агент аналітик креативів, <- дослідження) -> Агент по ТЗ -> Агент копірайтер + Агент креативщик -> Агент перевірки якості -> менеджер -> замір результату аналітиком.
Далі по одному агенту: налаштування кожного (вхід, вихід, запуск, поля), починаючи зі стратега.

## Етап 1 моделі агентів (2026-10-23): один агент на відділ, клієнти як черга
Спека: `docs/agent-model-spec.md`. Зроблено локально (на прод не виставлено, міграції 20261040 і 20261041 НЕ застосовані):
- Шість глобальних агентів відділу креативів (team `creative`, `ag_agents` по одному на роль), клієнт підключається рядком `ag_agent_clients` (увімкнено, режим авто/вручну/пауза, пріоритет, підтвердження перед передачею, свої поля клієнта, розклад агента для цього клієнта). Завдання несуть `campaign_id` і `request_id`.
- Рушій: черга клієнтів за пріоритетом; режим «вручну» (ланцюжок не стартує такий крок сам, є кнопка «Запустити для цього клієнта»); «підтвердження перед передачею» (результат чекає ОК, дія `pass_on`); пауза клієнта; тижневий Агент аналітик креативів працює по кожному клієнту окремо (стан розкладу в рядку клієнта), клієнт без Meta отримує примітку «немає даних» без витрат.
- Ланцюжок запиту: Агент креативний стратег (до 3 напрямків, читає картку проєкту, поля клієнта, дослідження інших відділів із віком звіту, аналіз креативів; якщо дослідження немає або застаріло, читає сайт сам) -> Агент по ТЗ -> Агент копірайтер + Агент креативщик -> Агент перевірки якості (поки лише вердикт, без циклу переробки) -> менеджер.
- Інтерфейс: у картці кампанії блок «Відділ креативів» (запити, форма, вікно запиту з ходом роботи, станами кроків, планом стратега, концепціями, текстами й запитами для Higgsfield).
- Тести: 142 перевірки, зокрема два сценарії на стенді (ланцюжок із збоєм і повтором, пріоритети, ручний режим, підтвердження, пауза, тижневий аналітик).
Не зроблено: сторінка агента з вкладками Огляд / Здоров'я / Проєкти / Налаштування / Журнал (етап 2), майстер кампанії з підключенням і автозаповненням (етап 3), цикл переробки Агента перевірки якості, генерація картинок Higgsfield, налаштування кожного агента (етап 4).

## Етап 2 моделі агентів (2026-10-23): сторінка агента відділу
Картка агента відділу креативів на карті відкриває його сторінку (`src/pages/Tools/agents/*`, реєстр: поле `deptAgent`; ручні інструменти копірайтера й перевірки якості лишаються кнопкою «Ручний інструмент»). Вкладки:
- **Огляд**: що в роботі зараз, проєкти агента з режимами, задачі в роботі з прогресом (кроки запиту «X з N»), помилки з кнопкою «Повторити», заплановані, нещодавно виконані.
- **Здоровʼя**: статус, стан, завантаженість (черга, виконується, помилки, середня тривалість), останній і наступний запуск, витрати за 30 днів, перезапуск (`restart_agent`: назад у чергу завислі й невдалі за 7 днів).
- **Проєкти**: клієнти агента в порядку черги, ▲▼ пріоритет, зупинити / продовжити, режим авто / вручну / пауза, «передавати далі після мого ОК», «Запустити зараз» (аналітик).
- **Налаштування**: загальні поля агента, що агент знає про клієнта (поля клієнта й додаткові вказівки), промти з версіями, пробний запуск промту на реальних даних клієнта (`dry_run`: результат не зберігається, поруч результат поточної версії, «Зробити поточною»).
- **Журнал**: журнал викликів моделі агента.
Ключ ролі стратега змінено на `creative_strategy`, бо `creative_strategist` займає старий агент кампанії.
Не зроблено: ліміт витрат (поки лише показ), майстер кампанії з підключенням і автозаповненням (етап 3), цикл переробки перевірки якості, генерація картинок, налаштування агентів по одному (етап 4).

## Карта AI Agents і відділ креативів (2026-10-24)
- Колір агента відділу на 3D-карті береться з його власних таблиць (`src/lib/agents/deptRunState.js`): проблема (невдале завдання або невдалий останній запуск, червоний), працює (завдання виконується або чекає в черзі, зелений), на паузі (агента вимкнено, або всі клієнти зупинені чи на паузі, або результат чекає вашого ОК, жовтий), очікує (блакитний). Проблема важливіша за роботу; вимкнений агент не вважається «у проблемі». Хук `useAgentRunStates` зливає це зі станом решти агентів.

## ИТОГОВЫЙ ПЛАН отдела креативов (2026-10-25, согласован с пользователем; заменяет прежний порядок этапов)
Причина пересмотра: комментарий руководства (идеи идут тремя путями: от конкурентов через Ad Library, из головы/ИИ, микс; сначала материалы, потом идея; ТЗ называет материал, откуда он и где размещать текст; кнопка CTA обязательна, кроме части fashion; форматы по площадке) и пример задачи mellowdiamond (готовые тексты, 5 текстов, плашка «FALL SALE · 15% OFF»). Higgsfield это ОСНОВНОЙ инструмент, дизайнер второстепенный.

### Решения
- Higgsfield рисует только картинку (референсы реального продукта); текст, плашка и кнопка накладываются шаблоном программно (HTML -> картинка, как в Image Studio), слова всегда ровно те, что дал менеджер. Текст от модели не доверяем.
- Тексты могут быть заданы менеджером (используются дословно) или написаны Агентом копірайтер (только если не заданы). Число креативов = число заданных текстов (не лимит «до 3»), форматы из платформы кампании (Meta feed/stories; Google свои размеры, точный список сверить по документации).
- Стратег читает сайт, Figma (кадры как картинки, цвета, шрифты; токен Figma только чтение кладёт пользователь в Vercel), скриншоты рекламы конкурентов, загруженные менеджером (Ad Library автоматически не вывозится); режим идей: конкуренты / свои / микс; первая часть работы стратега = инвентаризация материалов (есть / нет / что сгенерировать).
- Видео позже.

### Откуда данные
- Менеджер (форма запроса): задача, готовые тексты, оффер, ссылка Figma, источник идей, скриншоты конкурентов.
