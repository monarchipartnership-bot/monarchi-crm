# Модель агентів: один агент на відділ, клієнти як черга (узгоджено 2026-10-23)

## Рішення власника
- **Агент це один працівник відділу** з чергою клієнтів, а не копія на кожну кампанію. Причина: копії на кожного клієнта плодять десятки агентів і навантаження на платформу.
- Починаємо з **Відділу креативів**, потім по ланцюжку далі (інші відділи переводимо по одному).
- Агент працює і в **автоматичному**, і в **ручному** режимі (ручний: тільки за командою або з підтвердженням перед передачею далі).
- Нічого не публікується й не вантажиться в кабінети: результат іде менеджеру.

## Що спільне, що своє для клієнта
| Спільне для всіх клієнтів (рядок агента `ag_agents`) | Своє для клієнта (рядок зв'язку `ag_agent_clients`) |
|---|---|
| промти й версії, розклад, загальні налаштування, модель | включено чи ні для цього клієнта |
| одна сторінка, один журнал, один стан здоров'я | пріоритет у черзі, режим (авто / ручний / пауза) |
| ланцюжок: хто кому передає (`ag_links`, обов'язкові й ні) | інформація про клієнта, додаткові вказівки |
| | які агенти беруть участь у ланцюжку клієнта (обов'язкові й відключаємі) |

## Дані
- `ag_agents`: глобальні агенти відділу (team `creative`, scope internal), по одному на роль.
- `ag_agent_clients` (нова): agent_id, campaign_id, enabled, mode (`auto|manual|paused`), priority, confirm_before_pass (передавати дальше тільки після ОК менеджера), config (поля клієнта), останній запуск.
- `ag_campaigns` залишається «клієнтом у роботі» (проєкт, платформи, статус); майстер створення кампанії підключає клієнта до агентів відділу, а не створює копії.
- `ag_tasks.campaign_id` (нова): чия це задача; `request_id` лишається для запитів на креативи.
- Журнал (`ag_runs`) один на агента, з позначкою клієнта через завдання.

## Сторінка агента (вкладки)
1. **Огляд**: проєкт у роботі зараз, усі проєкти, поточні задачі зі статусом і «% виконання» (кроки ланцюжка запиту, X з N), заплановані задачі.
2. **Здоров'я**: статус, стан, завантаженість (черга, виконується), останній і наступний запуск, перезапуск, витрати за місяць і ліміт.
3. **Проєкти**: перелік клієнтів агента, зупинити / продовжити, змінити пріоритет, режим.
4. **Налаштування**: інформація агента (додати, виправити, видалити), промти з версіями, **тест промтів на реальних даних без запуску в роботу** (результат поруч із нинішньою версією, кнопка «зробити поточною», вартість пробного запуску показується до старту).
5. **Журнал**: який промт, що на вході, що на виході, скільки коштувало.

## Етапи будови
1. **Модель і рушій** (міграція, глобальні агенти відділу креативів, черга клієнтів з пріоритетом і режимами, тести на стенді).
2. **Сторінка агента** з вкладками вище, відкривається з картки агента на карті.
3. **Майстер кампанії**: підключення клієнта до агентів, учасники ланцюжка, автозаповнення з картки проєкту.
4. **Настроювання агентів по одному** (спершу Агент креативний стратег), потім інші відділи.

## Вхід Агента креативний стратег (затверджено)
- Автоматично з картки проєкту: назва й клієнт, сайт, країна, тип бізнесу, послуги, нотатки й додаткова інформація, менеджер, часовий пояс.
- З кабінету: поточні креативи (Meta: топ оголошень за 30 днів з картинкою, заголовком, текстом, кнопкою, результатом; Google: тексти оголошень і картинки медійних форматів, вибірку для Google ще треба дописати).
- Від інших агентів: Агент дослідження бізнесу, Агент дослідження конкурентів, Агент аналітик креативів, з датою звіту й позначкою «свіжий / застарів (старше 14 днів)».
- Вручну при запуску: мета періоду або запиту, пріоритет, бюджет на креативи, обмеження, дедлайн.
- Запуск: за запитом менеджера й за планом (раз на два тижні); напрямків за запит до 3.
