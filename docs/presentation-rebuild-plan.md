## 0. Где наши решения расходятся с промтом из пакета

Промт пакета писался под старый движок. Мы решили иначе, и это приоритетнее:

| Промт пакета | Наше решение |

| Один экспорт: PDF | PDF и PPTX на выбор |

| PDF через html2canvas | `html-to-image` (уже в проекте, как в Image Studio) для PDF; PPTX собирается из данных, не из картинок |

Из пакета берём без изменений: общий интерфейс (панель Дані / Дизайн / Слайди, большой холст 16:9, инспектор справа, лента слайдов снизу), палитру и токены, 3 стиля, фоны Meta/Google, 11 типов слайдов, правила типографики, галерею «Додати готовий слайд», иконки из `design-system/` (action-icons.svg + реестр), правило «не выдумывать данные».

## 1. Что получает пользователь

1. **Вход.** Из Тижневий/Місячний звіт кнопка «Створити презентацію» (проект и период подставлены). Из сайдбара «Презентація»: выбрать проект, тип периода, период. Данные берутся из сохранённого отчёта. Если отчёта нет, предложение создать его (ссылка на конструктор отчёта).
2. **Режимы** (панель вверху, как на макете):
   - **Дані**: проект, платформа (Meta/Google, если у проекта обе), период, источник = отчёт проекта, кнопка «Підтягнути зі звіту» (перезаписывает слайды только после подтверждения), название клиента и период (общие поля), язык слайдов (EN по умолчанию, UA).
   - **Дизайн**: 3 стиля (Brand Pulse, Monarchi Impact, Plum Editorial). Платформа задаёт фон обложки. Смена стиля не стирает правки текста.
   - **Слайди**: редактирование, порядок, скрытие, удаление, миниатюры.
3. **Холст** 960×540, масштаб под экран, подсказка «Натисніть текст, щоб редагувати».
4. **Лента слайдов** снизу: колесо мыши, стрелки, клик, миниатюры с номером и названием, меню «⋮» (показать/скрыть, удалить, влево/вправо). Последний слайд удалить нельзя.
5. **Редактирование текста** (только вручную, агенту недоступно): плавающая панелька у блока + инспектор «Текст» справа.
   - шрифт, размер (12–96), насыщенность, **B / I / U**, цвет (палитра + HEX), выравнивание (лево/центр/право), межстрочный и межсимвольный интервал, маркированный и нумерованный список, «Скинути форматування».
   - Форматирование применяется к выделенному фрагменту (внутри абзаца), выравнивание и интервалы к абзацу.
   - При смешанном выделении показывается «змішано», а не случайное значение.
6. **Шрифты.** Фирменные: Onest, Barlow Condensed, Cormorant Garamond. Стандартные «как в PowerPoint»: Arial, Calibri, Times New Roman, Cambria, Courier New, Georgia, Verdana, Tahoma, Trebuchet (список уточним). В окне предпросмотра и PDF они рисуются свободными двойниками с теми же размерами букв (Arimo, Carlito, Tinos, Caladea, Cousine, Gelasio и т.п.), поэтому переносы строк в PDF и в PowerPoint совпадают. В PPTX записывается настоящее имя шрифта.
7. **Готові слайди.** Кнопка «+ Додати слайд» открывает галерею (Усі / Основні / Метрики / Текст) с 11 живыми макетами в текущем стиле и платформе (платформа только для чтения). Выбор карточки только выделяет, «Додати слайд» вставляет после выбранного (позицию можно изменить). Пустые макеты содержат подсказки-заглушки, а не выдуманные цифры. Escape и «Скасувати» ничего не меняют.
8. **Картинки.** Вставка логотипа клиента или скриншота в слайды с блоком «Зображення» (макеты текст+картинка и титульный). Загрузка с автосжатием.
9. **Экспорт:** меню «Завантажити» с пунктами PDF и PPTX. При ошибке: понятное сообщение и «Повторити», колода не теряется.
10. **Сохранение:** автосохранение колоды вместе с отчётом (черновик, потом «готова»), открытие сохранённой колоды из списка отчётов.

## 2. Модель данных

Колода (JSON) = `{ version, projectId, reportId, platform, style, lang, meta: { client, period, ... }, slides: [...] }`.

Слайд: `{ id, type, hidden, data }`. Типы: `title, agenda, section, metricslist, kpigrid, campaignTable, dynamicsTable, table, bullets, paragraph, closing`.

Текст хранится не как HTML, а как **абзацы с фрагментами**: `paragraphs: [{ align, lineHeight, list, runs: [{ text, bold, italic, underline, font, size, color, spacing }] }]`. Пустые поля = «берётся из стиля». Из этого же рендерятся слайд, превью, PDF и PPTX, поэтому всё совпадает, а санитайзинг не нужен: вставленный HTML разбирается в фрагменты по белому списку (script, обработчики, `javascript:` отбрасываются на этапе разбора).

Общие поля (клиент, период): правка на слайде меняет общее значение везде (одно поведение, без «локальных отвязок»).

Числа в слайдах считаются кодом из данных отчёта (`reportMetrics`/`periodReport`), не вводятся руками и не проходят через текстовый редактор.

Генератор `buildDeckFromReport(report, { platform, style, lang })`: чистая функция без интерфейса. Её же будет вызывать AI-агент (стиль и платформа задаются при подключении агента к проекту, редактор текста агенту не нужен).

Соответствие слайдов данным отчёта:
- title: клиент, период, платформа; agenda: список разделов;
- metricslist: строки метрик с цифрами (все, с разбиением по страницам);
- kpigrid: 4–6 ключевых показателей для типа проекта (ecom / leadgen);
- campaignTable: колонки = группы кампаний, строки = метрики (как в таблице менеджеров);
- dynamicsTable: метрика / предыдущий период / изменение / текущий (без зелёной раскраски всех плюсов);
- bullets: «Що зроблено», «Плани»; paragraph: «Висновки»; table: произвольная; section, closing.

## 3. Технические решения

- **Рендер слайдов:** React-компоненты на 960×540 (`.pres-slide`), три стиля × 11 типов. Миниатюры и галерея это те же компоненты в уменьшенном масштабе (без скриншотов), поэтому быстро и всегда актуально.
- **Редактирование:** `contenteditable` по блокам, состояние читается в абзацы и фрагменты по событиям ввода. Выделение сохраняется при клике по панели и выпадающим спискам (сохранить диапазон, вернуть после применения).
- **Отмена/повтор:** стек снимков колоды (фиксируются при завершении ввода и при командах панели), Ctrl+Z / Ctrl+Shift+Z.
- **Переполнение:** замер после `document.fonts.ready`. Для данных (метрики, таблицы, списки) автоматическая пагинация по высоте. Для ручного размера шрифта: предупреждение «текст не помещается», ничего не обрезается.
- **PDF:** каждый слайд снимается в 960×540 (x2), собирается в `jsPDF`. Перед снимком: шрифты и картинки загружены, редакторские элементы (рамки, панели) исключены. PDF растровый: текст не выделяется (так же, как в старом разделе).
- **PPTX:** библиотека `pptxgenjs` (добавить в зависимости). Слайд = фон-картинка + настоящие текстовые блоки и таблицы. Размеры: 960 px = 10 in, 1 px = 0,75 pt. Жирный, курсив, подчёркивание, шрифт, размер, цвет, выравнивание, списки переносятся как свойства текста и редактируются в PowerPoint. Ограничение: PowerPoint не умеет вшивать шрифты через эту библиотеку (см. вопрос 1).
- **Шрифты:** локальные файлы (Onest, Barlow, Cormorant из пакета + двойники для стандартных), через `@fontsource` или файлами в `public/fonts`.
- **Хранение:** новая таблица `project_decks` (project_id, report_id, period_type, period_start, platform, style, lang, status, slides jsonb, updated_by/at; RLS как у `project_reports`). Картинки: пока сжатые data-URL внутри колоды (до ~400 КБ на картинку, до 6 на колоду). Хранилище файлов позже, если понадобится. Миграцию пишу я, применяете вы.

Скриншоты трёх состояний и готовые PDF/PPTX как доказательство.

## 5. Риски

- Редактор текста внутри `contenteditable` самый трудоёмкий и хрупкий блок (выделение, вставка, списки). Идёт отдельным этапом с собственными тестами.
- PPTX: фирменные шрифты у получателя не установлены, PowerPoint подставит другой (см. вопрос 1). Перенос строк может чуть отличаться от PDF.
- Cormorant и Barlow: курсив только там, где есть файл начертания (Cormorant есть, у Barlow Condensed в пакете нет). Недоступное начертание выключается, а не подделывается.
- Иконки: использовать только `action-*` из спрайта пакета (создание, скачивание, закрытие, корзина и т.д.), сверив с уже имеющимися иконками CRM, без новых рисунков.
