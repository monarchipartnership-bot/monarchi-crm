# Дизайн Mon'Archi CRM: бриф для дизайн-чату

Цей файл читають першим у кожній дизайн-сесії. Тут зафіксовано, що вже вирішено, як ми працюємо і де зараз розбіжності. Код CRM: `app/` (React 19 + Vite). Продакшн: https://crm.monarchi.agency.

## Як працюємо (процес)

1. **Спершу референси.** Власник називає 2–3 сайти/екрани, які подобаються, або дизайнер бере їх через плагін з реальними сайтами. Без референсу макет не починаємо.
2. **Макет до коду.** Варіанти показуємо живою сторінкою (Artifact або HTML-файл) з фірмовими кольорами, реальними іконками й лічильниками з CRM, з нижнім боксом, щоб було видно стик. Мінімум 3–5 варіантів, клікабельні.
3. **Власник обирає** літеру або каже, що змішати. Нічого не пишемо в CRM, поки не обрано.
4. **Реалізація в точності по макету**: той самий розмір, відступи, радіуси, тіні, кольори. Якщо щось неможливо в CSS, одразу кажемо, а не спрощуємо мовчки.
5. **Перевірка скріншотом** на проді або в dev-сервері до того, як показувати результат. Порівнюємо з макетом. Правимо, доки збігається.
6. **Без ефектів наведення за замовчуванням.** Питаємо кожного разу (виняток: motion kit нижче, його власник замовив).
7. Квадрати й кола замість задуманого малюнка означають, що пропущено крок 2: власник має бачити картинку до коду.

## Закріплена дизайн-система (не вигадувати нове)

- **Бокси.** Стандарт: білий, `1px solid var(--border)`, радіус 16px, тінь `0 4px 18px rgba(80,30,100,.07)` (еталон `.client-profile-side-card`). Кольоровий «tinted stage card» (`color-mix(... 9%, #fff)`) лише для реальних категорій зі своїм кольором (колонки угод, KPI за типом). Матове скло лише на Home (`.greet-card`, `.ti-card`).
- **Іконки.** Один стандарт: градієнтний бейдж (`linear-gradient(135deg, світлий, темний)`) + біла іконка + мʼяка тінь. Плоскі пастельні квадрати для нових бейджів заборонені. 3D-іконки сторінок (Soft Volume) з `src/lib/pageIcons.js`, іконки дій з `ActionIcon` (спрайт `public/icons/action-icons.svg`).
- **Кнопки.** Три рівні: головна `.btn.btn-p` (яскравий фіолетовий градієнт, одна на екран), статусна `.deal-btn-won/-lost/-reopen/-finish/-soft`, звичайна `.btn` (світла матова). Опасні `.btn-danger`, `.btn-move`. Нових стилів кнопок не вигадувати.
- **Випадаючі списки.** Лише компонент `Select` (`.ui-select*`), без нативного `<select>`.
- **Бейджі.** «Platform-logo pill» для логотипів платформ (бліда градієнтна заливка бренду, бренд-текст), tinted-stage для статусів.
- **Кольори бренду.** Слива `#682768`, акцент `#AE40AE`, градієнт `#B544B5 → #661466`, лінія `#EBC6EB`, фон `#F9EDF9`, текст `#270827`, приглушений `#883288`. Шрифт Onest.
- **Рух (motion kit).** `src/styles/motion.css`: підйом іконки при наведенні на бокс (620 мс), один прохід блиску на головній кнопці (650 мс). Не діє в `.ai-immersive`. Нова іконка підключається додаванням бокса й іконки у два списки в цьому файлі.
- **Розділ AI Agents** має власну «plum immersive» тему (`.constellation-page.ai-immersive`). Її не чіпаємо й не змішуємо з рештою.
- **Мова інтерфейсу.** Українська. Чат із власником: російська.

## Відомі розбіжності (чистимо по одній, за замовленням)

- Сторінки, які ще не отримали нову дизайн-систему (старі плоскі бокси, нативні select, пастельні бейджі). Список «ретрофіт на вимогу».
- Перемикач платформ на `/projects` (папки) замінюється: власнику сподобалися варіанти C (картки-лічильники) та E (капсули з сяйвом). Макети: `platform-switcher-variants.html`.
- Компактність: власник двічі просив зменшити «завеликі» елементи (вкладки, картки проєктів, кнопки). Нове робимо компактним за замовчуванням: висота контролів 32–36px, вкладок до ~70px.

## Як підключити нове в дизайн-чаті

Плагіни: design (критика, дизайн-система, доступність), «ground design in real websites» (1100+ сайтів, виміряні шрифти/відступи/палітра), 21st (компоненти). Коннектори з авторизацією власника: Figma, Canva. `/design-sync` для claude.ai/design.
